1. Introduccion y Objetivos

1.1 Introduccion

En el ambito de la ingenieria de software moderna, la integracion continua y la entrega continua representan metodologias indispensables para asegurar calidad sostenida y entregas predecibles. La optimizacion de pipelines permite a los equipos de desarrollo reducir tiempos de ciclo, maximizar la eficiencia del hardware anfitrion y obtener retroalimentacion automatizada sin friccion.

1.2 Objetivos de la Practica

  • Configurar un pipeline de entrega continua completo sobre una aplicacion web y API funcional denominada inventario-api.
  • Implementar la estrategia de branching Trunk Based Development como patron de integracion agil.
  • Incorporar etapas rigurosas de calidad incluyendo analisis de estilo con ESLint, pruebas unitarias con Jest al 100 por ciento de cobertura, pruebas funcionales con Selenium WebDriver en Chrome headless y analisis estatico de SonarQube.
  • Configurar notificaciones post ejecucion enviadas en tiempo real hacia la API de GitHub para los estados pending, success y failure.
  • Validar documental y experimentalmente las cuatro estrategias de optimizacion: ejecucion paralela, cache de dependencias, ejecucion selectiva y pipelines modulares reutilizables.

2. Arquitectura de la Solucion

2.1 Aplicacion Funcional: inventario-api

El sistema consiste en una API REST desarrollada en Node.js y Express para la administracion de instrumentos musicales. La solucion incluye:

  • Endpoints REST para gestion de recursos: operaciones completas de lectura, filtrado por categoria, consulta individual, creacion validada, actualizacion y borrado.
  • Interfaz web estatica en public/index.html servida por Express para permitir la inspeccion visual del catalogo y la realizacion de pruebas automatizadas con navegador.
  • Conjunto de 7 pruebas automatizadas con Jest y Supertest en tests/app.test.js con cobertura perfecta de lineas.
  • Suite funcional en tests/selenium.test.js utilizando Selenium WebDriver con Chrome en modo headless.
  • Reglas de sintaxis estricta definidas en .eslintrc.json.

2.2 Infraestructura y Herramientas

  • Servidor de Automatizacion: Jenkins ejecutandose sobre Windows como servicio de sistema.
  • Interprete de Comandos: PowerShell nativo para asegurar ejecucion fiable en Windows.
  • Version de Java: Eclipse Temurin JDK 21 LTS.
  • Version de Node: Node.js 22 con npm.

2.3 Estrategia de Branching: Trunk Based Development

Se establecio Trunk Based Development como modelo de flujo de trabajo:

  • Rama main: Tronco principal permanentemente listo para ser entregado a produccion.
  • Ramas de Caracteristica: Ramas cortas y de rapida integracion creadas a partir de main.
  • Politica de Pipeline: Las ramas secundarias ejecutan pruebas y calidad en paralelo, mientras que la rama main ejecuta adicionalmente el analisis estatico, empaquetado, despliegue a staging y la compuerta de aprobacion hacia produccion.

3. Estructura y Etapas del Pipeline de Entrega Continua

El archivo Jenkinsfile orquesta las siguientes fases secuenciales y concurrentes:

Etapa del Pipeline Herramienta Utilizada Comportamiento y Descripcion
Checkout Git SCM y Modulos Groovy Descarga la revision y carga dinamicamente ci/stages.groovy y ci/notify.groovy. Notifica estado pending a GitHub.
Instalar dependencias Job Cacher y npm ci Restaura el directorio node_modules a partir del hash de package-lock.json.
Calidad de codigo Bloque Parallel Ejecuta simultaneamente ESLint, Jest con JUnit y cobertura, Selenium WebDriver y auditoria de seguridad.
SonarQube PowerShell y sonar-project.properties Valida los parametros de calidad estatica del proyecto en la rama main.
Build scripts/build.js Empaqueta el codigo productivo en dist/ y archiva artefactos en Jenkins con firmas digitales.
Deploy a Staging scripts/deploy.ps1 Despliega automaticamente los artefactos verificados en el entorno de pruebas staging.
Deploy a Produccion Jenkins Input Step y PowerShell Pausa la ejecucion requiriendo aprobacion manual del usuario antes de desplegar en produccion.
Post Actions ci/notify.groovy y GitHub API Archiva reportes y emite el estado final success o failure hacia GitHub.

4. Demostracion de las Cuatro Estrategias de Optimizacion

Resumen de Cumplimiento: Se implementaron de forma real y comprobable las cuatro tecnicas solicitadas en las instrucciones de la catedra.

4.1 Optimizacion 1: Ejecucion Paralela

En la etapa de calidad de codigo, las cuatro subtareas se declaran dentro de una directiva parallel de Jenkins. En lugar de sumar los tiempos individuales de ejecucion de ESLint, Jest, Selenium y npm audit, el tiempo total se reduce al tiempo que toma la subtarea mas exigente. Los registros del build numero 4 confirman que las cuatro tareas se dispararon en el mismo segundo.

4.2 Optimizacion 2: Cache de Dependencias

Mediante el plugin Job Cacher en ci/stages.groovy, se configuro un almacenamiento en cache para node_modules vinculado a package-lock.json. En el build numero 4, el log de Jenkins certifico:

Cache for node_modules with id 3ec03583f8eaec275cb2183db769ff47
Found cache in job specific caches
Restoring cache...
Cache restored in 3274ms

La restauracion de paquetes tomo unicamente 3.2 segundos, evitando transferencias repetitivas de red.

4.3 Optimizacion 3: Ejecucion Selectiva por Ramas y Etapas

La funcion hayCambiosDeCodigo inspecciona los archivos modificados mediante git diff. Cuando un desarrollador trabaja en una rama de caracteristica y unicamente modifica documentacion markdown en docs o archivos con extension .md, el pipeline omite las etapas de calidad. Ademas, las fases de SonarQube, despliegue a staging y despliegue a produccion estan condicionadas unicamente al tronco main.

4.4 Optimizacion 4: Pipelines Modulares y Reutilizables

Toda la logica operativa se desacoplo del Jenkinsfile central y se distribuyo en dos modulos independientes:

  • ci/stages.groovy: Expone funciones reutilizables como instalar, lint, tests, selenium, sonar, build y desplegar.
  • ci/notify.groovy: Expone funciones reutilizables para emitir estados y comunicarse con la API de GitHub.

6. Conclusiones

  1. Se configuro con exito un pipeline de entrega continua integral bajo el estandar Trunk Based Development, integrando etapas de build, analisis de estilo, pruebas unitarias, pruebas funcionales con Selenium, verificacion de SonarQube y despliegue por entornos.
  2. Las cuatro tecnicas de optimizacion exigidas en la guia practica se implementaron y verificaron en ejecuciones reales, logrando concurrencia paralela, reutilizacion de cache en 3 segundos, selectividad por rutas de archivo y modularidad desacoplada en Groovy.
  3. La incorporacion de Selenium WebDriver en modo Chrome headless permitio robustecer la suite de calidad validando la experiencia de usuario final dentro del mismo pipeline sin intervencion manual.
